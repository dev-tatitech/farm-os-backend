FarmOS API documentation

Tati FarmOS backend · Django Ninja · version 1.0

This guide is for product and engineering. Every endpoint lists what you send (URL pieces, query string, JSON body) and a sample JSON response. Field names match the live OpenAPI schema generated from the code.

How to call the API

Base URL Local Docker: http://127.0.0.1:8000 or Nginx http://127.0.0.1:8081. All routes below are prefixed with /api.

Docs Interactive Swagger UI: /api/docs. Raw OpenAPI: /api/openapi.json.

Auth After POST /api/auth/login the server sets cookies named {app}_access_token, {app}_refresh_token, and {app}_csrf_token. app is client or admin depending on the request host. Send cookies on later requests. For unsafe methods, send header X-CSRFToken matching the CSRF cookie.

JSON Most bodies are application/json. A few animal-create routes use multipart/form-data so you can attach an image. Dates are YYYY-MM-DD. Datetimes are ISO-8601. Money examples use NGN.

Permissions Most farm endpoints load the current user from the access cookie, resolve their organization, then check a permission code (for example add_animal_details) optionally scoped to that farm. Missing permission returns HTTP 403 with the envelope below.

Standard success envelope

{
  "success": true,
  "message": "Human-readable summary",
  "data": {}
}

Standard paginated list

{
  "success": true,
  "message": "Fetched successfully",
  "data": [],
  "num_pages": 3,
  "current_page": 1,
  "total_items": 42,
  "has_next": true,
  "has_previous": false
}

Typical errors

{
  "success": false,
  "message": "Permission denied",
  "data": null
}

Login failure uses a smaller shape: {"status": "Error", "message": "Invalid credentials"}. Some OTP failures return {"detail": "..."}.

v1 vs v2: older animal/farm/dashboard routes use species_id, breed_id, and unit_id. v2/v3 routes use livestock master data: livestock_species_id, livestock_breed_id, housing_unit_id. Prefer v2/v3 for new clients.

Authentication

POST/api/auth/new-account

Create Account

Registers a user with email + password. Sends a 6-digit OTP and sets an email cookie used by /email-validate.

Auth Public (no login cookie)

JSON body fields (input)
FieldTypeRequiredWhat to send
emailstring (email)yesAccount email. Used as the login username.
passwordstringyesAccount password. Must pass Django password validators.
confirm_passwordstringyesMust match password.
Example request body
{
  "email": "farmer@example.com",
  "password": "Str0ngPass!word",
  "confirm_password": "Str0ngPass!word"
}
Example JSON response (output)
{
  "success": true,
  "message": "Account created successfully"
}
