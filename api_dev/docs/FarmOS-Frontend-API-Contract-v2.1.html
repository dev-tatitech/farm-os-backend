Building the frontend for African Agriculture

Official Web/Mobile contract v2.1 · sandbox http://127.0.0.1:8082/api/v2/ · Swagger /api/v2/docs

v2.1 completes v2.0 — it does not rewrite it. Every route below is what new screens should call. Brand primary from tatifarmos.com: #209850.

How frontend should call this API

Base Nginx sandbox http://127.0.0.1:8082 · direct app http://127.0.0.1:8001. Live stack is unchanged on 8081/8000.

Prefix Official contract is /api/v2/ version 2.1. Legacy /api/* (240 routes) stays for existing clients. Do not mix envelopes. GET /api/v2/registry/ lists v2 vs approved-legacy vs deprecated.

Auth POST /api/auth/login sets client_access_token (HTTP-only). Send cookies on v2 requests. Unauthenticated v2 calls return AUTHENTICATION_REQUIRED.

IDs Use livestock_species_id, livestock_breed_id, housing_unit_id, integer farm_id / animal_id, UUID organization_id / user ids. People screens use display_name. Tasks and timeline include actor, subject, source, result.

Idempotency On writes send client_request_id in JSON or header X-Client-Request-Id. Same key + same user returns the first JSON body and must not create a second vaccination/feed/sale.

Timezone Dashboard clocks use Africa/Lagos.

What’s new in 2.1

Animal list + PATCH, optional untagged create (INT-…), statuses transferred_out / culled, people/roles/permissions GETs, unable-to-complete + reopen, schedule GET/PATCH/deactivate + due-schedule runner, observation create_case, case detail, health alerts, health dashboard, unread-count, weight / pregnancy_check / mortality complete handlers. Reproduction, feed, finance, reports, movement, and master data stay on approved legacy /api/*.

Ibrahim vaccination flow

  1. Owner POST /operations/tasks/ with task_type: vaccination and Ibrahim’s assignee_id.
  2. Ibrahim GET /operations/my-work/ — task is in data[].
  3. POST .../accept/ then optional .../start/.
  4. POST .../complete/ with vaccine_name + date_given (+ client_request_id).
  5. Backend writes the existing VaccinationRecord, emits timeline events, creates a follow-up task if next_due_date is set, and the task leaves My Work.
  6. Retry the same complete with the same client_request_id — still one vaccination row.
